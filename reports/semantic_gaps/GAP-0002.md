# GAP-0002 — Function evaluation and executable dependency chains

## Exact mathematical reasoning requirement

Evaluate a definition through its dependency graph: from `f(x) = x + 1` and
`g(x) = 2f(x)`, compute `f(3) = 4` and then `g(3) = 8`.

## Trajectories/examples

- G03, actions `a0`–`a2`.

## Current HML constructs inspected

- `hml_core/src/hamiltonian_lang/parser/__init__.py`: `def` declarations and call parsing.
- `hml_core/src/hamiltonian_lang/type_system/__init__.py`: function arity and type checks.
- `hml_core/src/hamiltonian_lang/backends/canonical.py`: definition identity and dependency
  structure.
- `hml_core/README.md`: the compiler is described as a representation/type-checking
  vertical slice, not an evaluator.

## Why they are insufficient

HML can represent and type-check the definitions and calls, but `hml check` does not execute
the definitions to produce a verified numeric result. The dependency graph is available as
structure, not as an execution trace with a computed value and local verification record.

## Classification

`EXPRESSIBLE_WITH_LIBRARY` — an evaluator or exact symbolic execution library could supply
the missing computation without changing the meaning of existing HML constructs.
